# ~/.claude 共通設定

Claude Code の全プロジェクト共通ルールを管理するリポジトリ。

![](./icons/icon_claude.png)

## 管理対象

| ファイル | 内容 |
| --- | --- |
| `CLAUDE.md` | 全プロジェクト共通のルール（ユーザーメモリ） |
| `rules/` | テーマ別に分けたルール置き場（現在は空） |
| `.gitignore` | ホワイトリスト方式。上記以外はすべて無視 |
| `README.md` | 本書 |

## 方針

- 共通ルールは「こだわり・基本方針」のみを書く。構成・コマンド・固有の注意点は各プロジェクトの `AGENTS.md`（`CLAUDE.md` は `@AGENTS.md` を取り込むだけ）に書き、食い違う場合はプロジェクト側を優先する。
- `.gitignore` は `/*` で全て無視し、必要なものだけ `!` で許可する。認証情報・履歴・設定が誤ってコミットされないようにするため。
- ルールが増えたら `rules/` にテーマ別に分割する。`CLAUDE.md` は200行未満を目安にする。
- 絶対に守らせたい制限（push禁止など）は `CLAUDE.md` の指示に頼らず、`settings.json` の権限設定で縛る。
- コミット前に `git add -n .` で、管理対象以外が含まれていないことを確認する。リモートリポジトリは private にする。

## CLAUDE.md の要約

- **プロジェクト側の方針ファイル**: `AGENTS.md` に書く（Claude Code と GitHub Copilot 共用）。プロジェクトの `CLAUDE.md` は `@AGENTS.md` を取り込むだけにする。
- **基本方針**: 回答・コメント・コミットメッセージは日本語。`docs/` の方針に従う。ドキュメントは `docs/`、指示の記録は `orders/order_YYYYMMDD.md` に置く。曖昧な指示や設計判断は実装前に質問する。
- **モデルの使い分け**: Sonnet系以下が前提で通常は Sonnet、軽作業は Haiku系。方針決定や大きな設計変更は決めず、`docs/` に従うか確認する。
- **Python**: プロジェクト直下の `.venv` を必ず使う。システムの Python に直接 `pip install` しない。依存関係は `requirements.txt` か `pyproject.toml` に記録する。
- **Git・コミット**: Step作業内のコミット・push は指示なしで行ってよく、それ以外は依頼されたときだけ。メッセージは「`<種別> <要約>`」で、日本人が読んで分かる具体的な日本語にする。1コミット1目的。認証情報・秘密鍵・`.env` はコミットしない。リリース時は `Version` と変更履歴を書き、バージョンは Git のタグで管理する（タグ付け・タグ push は依頼時のみ。付け方は事前にユーザーへ確認）。
- **ブランチ管理**: 計画時に実装を Step 単位に分けて `docs/TASK.md` に記載する。作業は main から `step<番号>/<内容>` のブランチを切って行い、main へ直接コミットしない。Step の区切りで、PR作成 → Squash マージ → マージ済みブランチ削除までを AI が行う。競合やテスト失敗時は止めて報告し、未マージブランチの削除・force push・main への直接 push は確認を取る。
- **安全上の注意**: 破壊的な操作は実行前に必ず確認を取る。
